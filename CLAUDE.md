## Project

A SCADA simulator for testing purposes, written in Go, emulating one or more HV circuit breakers at once. `cmd/scada-simulator/main.go` runs a single gRPC server on `Dms.Api.Scada.Grpc.{Host,Port}` hosting two services — the `TelemetryStream` service (`api/scada/telemetry.proto`) that clients — chiefly the DMS backend (see `api/scada/openapi.json`) — connect to: they Subscribe to points/tags, can send telecontrol (SupervisoryControl) commands, and can change a breaker's IEC 61850 Mod-style operating mode (SetMode: On/Blocked/Test/Off), all implemented in `internal/telemetryserver` backed by `pkg/breaker.Simulator`; and the `FaultSimulator` service (`api/scada/faultsim.proto`), a simulator-only addition (mirrors no real DMS/SCADA contract) letting a test harness or operator inject a `pkg/breaker.Measurement` into a named breaker to trigger a real trip/autoreclose sequence — sustained automatically (re-fed every 200ms) until a later call for the same breaker replaces it, so one fault injection persists across every reclose attempt until explicitly cleared with a lower value — implemented in `internal/faultsimserver` — plus a REST server (`internal/restserver`) implementing the two endpoints those clients need first: `POST /api/token` to log in, and `GET /api/external/telemetry/tags` to discover every tag ahead of any data arriving via Subscribe.

Module: `scada-simulator`, Go 1.26 (`go.mod`).

## Architecture

- `cmd/scada-simulator/main.go` — parses flags/config, builds one `pkg/breaker.Simulator` per entry in `config.Config.Breakers` into a `map[string]*breaker.Simulator` keyed by name (fatal on duplicate names or an empty list), logs each one's position/quality/protection/autoreclose status right after construction, and runs a single `google.golang.org/grpc` server on `Dms.Api.Scada.Grpc.{Host,Port}` with two services registered on it: `internal/telemetryserver.TelemetryServer` as `pkg/telemetry`'s `TelemetryStream` service, and `internal/faultsimserver.FaultSimulatorServer` as `pkg/faultsim`'s `FaultSimulator` service — plus an `internal/restserver` HTTP server on `Dms.Api.Scada.{Host,Port}`. Follows the shutdown pattern from the sibling `rdss-dms-rtdb` project: `signal.NotifyContext` → graceful shutdown (`http.Server.Shutdown`, `grpc.Server.GracefulStop`) with a timeout fallback to a hard `Stop()`. gRPC reflection is registered only when the log level is Debug or above.
- `internal/telemetryserver/` — implements all three `TelemetryStream` RPCs. `telemetry.go`: `NewTelemetryServer(ctx, breakers, logger)` starts exactly one long-lived `forward` goroutine per breaker (tied to `ctx`, the application's overall lifetime context) that converts each `breaker.Event` to tags, filters them through `dedupeForBroadcast` (drops any point whose value+quality exactly match the last one this server actually broadcast for that key — the simulator must never republish a tag unless its value or quality genuinely changed; `TelemetryServer.last map[string]lastPoint`, mutex-guarded, seeded per breaker from its initial `breakerSnapshot` in `NewTelemetryServer` via `seedLast` so this is correct from the very first real event, not just the second — `alwaysForward` exempts the pulse tags below and `"<name>.position"`, both of which must reach the client even when numerically unchanged), logs whatever survives at Trace level (`logUpdate`) **exactly once**, and broadcasts it to every currently connected `Subscribe` client's own channel (`TelemetryServer.subscribers`, mutex-guarded) — regardless of how many clients are connected (zero, one, or many), so the trace log is never duplicated per client. `Subscribe` itself does no event-to-tag conversion; it only registers/unregisters a channel and relays what it receives, after sending (and logging) its own one-time initial snapshot. Event-to-tag mapping (`dataPointsForEvent`): `EventPositionChanged` refreshes only `"<name>.position"`; `EventMeasurementChanged` refreshes the analog tags; `EventModeChanged` is the *only* source of `"<name>.mode"` updates (re-read via `sim.Position()`'s quality, since the event's `Detail` carries no quality of its own) — deliberately not derived from `EventPositionChanged`'s `Quality` field even though `SetMode` also emits that event, or every ordinary position change would resend an unchanged `.mode` value; the remaining protection/autoreclose-related kinds trigger a cheap re-read via `ProtectionStatus()`/`AutoRecloseStatus()` rather than hand-decoding each `Detail` type; `EventTrip`/`EventLockout`/`EventAutoRecloseSucceeded` additionally each push a one-shot `PROTECTION_EVENT`-typed pulse tag alongside that re-read (`"<name>.trip.protection"`, `"<name>.autoreclose.false"`, `"<name>.autoreclose.true"`, respectively — always value `true`, via `pulsePoint`) that carries no persistent value and is deliberately never part of `breakerSnapshot`'s initial snapshot, unlike every other tag — `DataPointType_PROTECTION_EVENT` (as opposed to `BOOLEAN`) is what flags these three as a discrete occurrence rather than a level-state a client should diff against its previous value; `EventAutoRecloseSucceeded` (`pkg/breaker`) is a small addition of its own — it fires when `autoReclose.OnReclaimElapsed()` returns true in `completeOperate`, i.e. the reclaim timer elapsed without a further trip, extending the pre-existing `EventTrip`/`EventLockout` pair (an unambiguously protection-caused trip, since `EventTrip` is only ever emitted from the protection-pickup path, never a manual/SCADA Open) with the "sequence finished successfully" counterpart `EventLockout` didn't cover. `SubstationRequest.Id` is ignored — every subscriber sees every configured breaker, since this simulator doesn't model a client/substation hierarchy. `control.go`: `SupervisoryControl` maps `key` = `"<breaker-name>.control"` and `value` (`0`=Open, `1`=Close) onto `BreakerController.Select`/`Operate`, tracking the pending `SelectionID` itself in `TelemetryServer.pending` (keyed by request `key`, mutex-guarded) since the proto message carries no field for a caller to echo one back; every call is logged at **Info** level twice (the request's key/value/flags, then the result, `moved` — whether the breaker's position actually changed, comparing `Position()` read before dispatch to after; false for a `Select`-only call, one with neither `Select` nor `Execute`, or an `Operate` that found the breaker already at target — and the breaker's *real, unmarked* position/quality/protection right before returning). `moved` exists so a caller can tell "did the switch flip" directly from this one log line rather than having to infer it by watching `"<name>.position"` for an `Intermediate` step on `Subscribe`. `Test` is a pure quality modifier layered on top of whatever `Select`/`Execute` already request — it never changes which action is taken (`Select` alone still only arms; neither set still does nothing) — via `setTestMode(name, req.GetTest())`, called unconditionally on every call (not just `Test` ones): while a breaker's test mode is on, `applyTestMode` ORs `qds.QdsTest` onto every quality value `telemetry.go`'s point-builders (`breakerSnapshot`, `measurementPoints`, `statusPoints`, `dataPointsForEvent`) compute for it, on both `Subscribe`'s snapshot and every forwarded update, until a later call explicitly sets `Test` back to `false`. `EventPositionChanged` (`pkg/breaker`) fires not just on a real position change but also as a confirmation when `Operate` is a no-op (command already matches current position) — otherwise a SCADA client re-issuing a command matching the current state would see no push at all. See "SCADA tag naming" in `pkg/breaker/README.md` for the full `<breaker-name>.<category>.<leaf>` tag scheme, and note the quality-reduction rationale in `qualityToProto` (deliberately not `qds.Quality.GetPriority`, which serves a different, wider purpose). `ProtectionTerminalSetMode` maps `key` = `"<breaker-name>.mode"` and `mode` (via `modeForProto`, `ProtectionTerminalMode` → `breaker.Mode`; `ERROR_NOT_SUPPORTED` only for `MODE_UNKNOWN`) onto `BreakerController.SetMode(mode, reason)`, reusing `ScadaSupervisoryControlResult` for its response rather than a parallel enum; it's logged the same twice-per-call way as `SupervisoryControl`, and its effect is enforced by `SupervisoryControl`'s existing pre-check — `qds.QdsBlocked` set *without* `qds.QdsTest` (`ModeBlocked`/`ModeOff`; deliberately excludes `ModeTestBlocked`, which sets both bits together and still accepts control — see below) — and surfaced on `Subscribe` via the same `"<name>.mode"` tag `EventModeChanged` already drives. This is independent of `SupervisoryControl`'s own per-request `test` flag/`testMode` map above — the two `qds.QdsTest` sources are deliberately not merged. `pkg/breaker.Mode` models all five of IEC 61850 Edition 1's Mod/Beh values, including `ModeTestBlocked` (4): function active and control accepted like `ModeTest`, but — like `ModeBlocked` — drives no physical output at all (`trip()` and `doOperate()` both special-case it alongside `ModeBlocked`, confirming a Select/Operate without ever calling `beginOperate`); `setMode` sets both `qds.QdsTest` and `qds.QdsBlocked` together on `posQuality` for it, which `qualityToProto` reduces to `DataPointQuality`'s distinct `QDS_TEST_BLOCKED` (checked before the singular `QDS_BLOCKED`/`QDS_TEST` cases) rather than either bit alone.
- `cmd/faultsim/main.go` — a standalone console client for `FaultSimulator.InjectMeasurement`, dialing a running `cmd/scada-simulator`'s gRPC server (`-addr`, default `127.0.0.1:50051`) over plaintext (`insecure.NewCredentials()`, matching this simulator's other clients/tests — no TLS anywhere in this repo). `-breaker` names the target (required); `-current`/`-voltage` accept either one number (applied to all three phases) or `"a,b,c"` for an asymmetric fault, parsed by `phaseFlag`; `-active-power`/`-reactive-power`/`-apparent-power`/`-frequency` are plain scalars. Prints the `InjectMeasurementResult` and exits non-zero on anything but `OK` (including `ERROR_BREAKER_NOT_FOUND`), so it composes in scripts. Each invocation is a single request, but its effect on the server persists — see `internal/faultsimserver`'s sustain behavior below — so one `faultsim` call is enough to fault a breaker through to Lockout; a second call with a lower `-current` clears it. See `cmd/faultsim/README.md` for usage and worked fault scenarios (instantaneous/inverse-time trip, sustained-fault lockout, asymmetric fault, clearing a fault) against `config/scada-simulator.yaml`'s sample breakers.
- `internal/faultsimserver/` — implements `FaultSimulator.InjectMeasurement` (`api/scada/faultsim.proto`), a simulator-only gRPC service (mirrors no real DMS/SCADA contract, unlike `TelemetryStream`) for driving a breaker's `pkg/breaker.EmulatorFeed` from outside the process. `Breaker` names the target in the shared `map[string]*breaker.Simulator` (`ERROR_BREAKER_NOT_FOUND` if unknown); the rest of the request maps 1:1 onto `breaker.Measurement` (`Current`/`Voltage` as `PhaseValues`, plus power/frequency scalars). A call is not a one-shot event: `sustain` feeds it to `sim.InjectMeasurement` immediately, then starts a goroutine that keeps re-feeding the same measurement every `sustainInterval` (200ms, a simulated sample rate) — replacing (cancelling) any goroutine already sustaining that breaker, tracked in `FaultSimulatorServer.sustainCancel` (mutex-guarded, keyed by breaker name) — until a later `InjectMeasurement` call for the same breaker supersedes it, or `NewFaultSimulatorServer`'s `ctx` (the application's lifetime context) ends. This is why a single fault injection (current above a breaker's configured pickup) persists across every autoreclose attempt through to Lockout on its own — a real fault stays on the line until actually cleared, not until some fixed timer expires — and why clearing one is just injecting a value back below pickup. `InjectMeasurement` never itself returns an error (see its `pkg/breaker` doc comment), so every call's only possible outcomes are `OK` or `ERROR_BREAKER_NOT_FOUND`. Logged at Info level twice, matching `internal/telemetryserver`'s pattern (request fields, then result).
- `internal/restserver/` — implements two endpoints from `api/scada/openapi.json`'s much larger REST API (see its package doc for what's out of scope). `POST /api/token`: an OAuth2-password-grant login (`username`/`password` form fields checked against `Dms.Api.Scada.{Username,Password}`) that hands back a freshly generated opaque bearer token — never actually validated anywhere afterward (neither this server nor `internal/telemetryserver`'s gRPC service checks it on any other call); it exists because real clients (e.g. `rdss-dms-rtdb/pkg/rest_client`) expect the login step to succeed and return a `TokenResponse`-shaped body. `GET /api/external/telemetry/tags`: every tag-id (with datatype) across every configured breaker, for provisioning a point before any data arrives via Subscribe — derived from `internal/telemetryserver.TagsFor` (the tag set `Subscribe`'s snapshot reports, plus the write-only `<name>.control` tag `SupervisoryControl` accepts and the three one-shot pulse tags `dataPointsForEvent` pushes on trip/lockout/autoreclose-succeeded, so all four can be provisioned too even though none ever appears in a Subscribe snapshot), grouped under one fixed placeholder substation entry (`substationName = "scada-simulator"`) since this simulator has no real client/substation hierarchy, same simplification `Subscribe` makes for `SubstationRequest.Id`.
- `internal/configuration/` — the application's own config schema (`Configuration` struct: `Logging`, `Dms.Api.Database.Dsn`, `Dms.Api.Scada.{Host,Port,Username,Password,Grpc.Host,Grpc.Port}`, `Breakers` (`[]pkg/breaker.Config`, one per emulated breaker)), read via `pkg/configuration`. `config/scada-simulator.yaml` is a sample config file matching this schema, including a `breakers:` list.
- `pkg/configuration/` — a generic, standalone (own LICENSE) YAML + environment-variable configuration loader. Struct fields opt into env-var overrides via an `env:"true"` tag alongside their `yaml:"..."` tag; `ReadFromEnv`/`ListEnv` walk the struct with reflection to derive env var names from the nested yaml tags (parent tag + `_` + field tag, upper-cased, optionally prefixed with `EnvVarPrefix`). `Read(file, s)` loads the YAML file then applies env overrides on top. Only scalar fields (string/bool/int/[]string) support `env:"true"`; nested structs/arrays like `pkg/breaker.Config` are YAML-only.
- `pkg/llog/` — a standalone (own LICENSE) leveled logger wrapping the standard `log` package (`Trace`/`Debug`/`Info`/`Warning`/`Error`), with a package-level `Logger` singleton set up in `init()`. Log level is configured via `internal/configuration`'s `Logging.Level` field. `pkg/breaker` does not import this package directly — it declares its own minimal `breaker.Logger` interface (`Warnf`/`Errorf`/`Infof`) and defaults to a no-op logger; attach `llog.Logger` (or any other logger with that method set) via `breaker.Config{}.WithConfig(llog.Logger)`.
- `pkg/qds/` — SCADA point-quality bitflags (`Quality`, a `uint32`), e.g. `QdsInvalid`, `QdsNoSource`, `QdsSubstituted`, `QdsAlarmLl`/`QdsAlarmUl`, etc. `GetPriority()` picks a single representative flag from a set bitmask by priority order (for things like choosing a badge/border color). Has real unit tests in `qds_test.go` — follow this package's table-driven style when adding tests elsewhere. `pkg/breaker` reuses `qds.Quality` rather than defining its own.

### `api/scada/`

`telemetry.proto` is the gRPC contract `cmd/scada-simulator/main.go`'s server implements (client/substation-scoped `Subscribe` point stream, plus `SupervisoryControl` for telecontrol commands and `ProtectionTerminalSetMode` for IEC 61850 Mod-style mode changes); its generated Go code lives in `pkg/telemetry/` (`telemetry.pb.go`, `telemetry_grpc.pb.go` — `DO NOT EDIT`, regenerate from the `.proto` instead). `faultsim.proto` is a separate, simulator-only contract (`FaultSimulator.InjectMeasurement`, implemented by `internal/faultsimserver`) with its own generated package `pkg/faultsim/` (own `go_package` option, own `DO NOT EDIT` generated files) — kept apart from `telemetry.proto` precisely because it mirrors no real backend contract the way that one does. `Makefile`'s `grpc.go` target compiles both `.proto` files in one `protoc` invocation. `openapi.json` is the broader external RDSS SCADA/DMS backend's full REST API (250+ endpoints: telemetry, alarms, select/confirm/execute/cancel control, DMS status/LFA, etc.) — only `POST /api/token` and `GET /api/external/telemetry/tags` are implemented here (`internal/restserver`), the rest is not — grep it rather than reading it whole, it's large.

### `pkg/breaker`

An in-memory HV circuit breaker + protection relay (IED) simulator exposing a SCADA-facing interface (`scada.go`), implemented per the design spec in `tmp/hvcbagentprompt.md` (gitignored, present in this checkout only — consult it before extending the protection/autoreclose model). See `pkg/breaker/README.md` for the SCADA-requirement-to-interface mapping and how to run its `Example`. Key pieces: `types.go` (`Position`, `Measurement`), `protection.go` (IEC 60255 curves, `OperateTime`), `autoreclose.go` (pure ANSI-79 state machine), `control.go` (select-before-operate, `errors.AsType`-friendly error types), `config.go` (`Config`, YAML-loadable), `events.go`/`scada.go` (interfaces), `simulator.go` (the concrete `Simulator` — a single run-loop goroutine owns all state; external calls go through `do`/`doCtx` closures posted over a channel, which is what keeps it race-free without a mutex).

## Conventions

- MIT-licensed subpackages under `pkg/` (`pkg/llog`, `pkg/qds`, `pkg/configuration`) each carry their own `LICENSE` file and are written to be usable independently of this application — avoid introducing dependencies from these packages back onto `internal/` or `cmd/`.
- Table-driven tests, following `pkg/qds/qds_test.go`.
