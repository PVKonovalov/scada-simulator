## Project

A SCADA simulator for testing purposes, written in Go, emulating one or more HV circuit breakers at once. `cmd/main.go` runs two servers: a gRPC server (the `TelemetryStream` service in `api/scada/telemetry.proto`) that clients — chiefly the DMS backend (see `api/scada/openapi.json`) — connect to: they Subscribe to points/tags and can send telecontrol (SupervisoryControl) commands, both implemented in `internal/telemetryserver` backed by `pkg/breaker.Simulator`; and a REST server (`internal/restserver`) implementing the two endpoints those clients need first: `POST /api/token` to log in, and `GET /api/external/telemetry/tags` to discover every tag ahead of any data arriving via Subscribe.

Module: `scada-simulator`, Go 1.26 (`go.mod`).

## Architecture

- `cmd/main.go` — parses flags/config, builds one `pkg/breaker.Simulator` per entry in `config.Config.Breakers` into a `map[string]*breaker.Simulator` keyed by name (fatal on duplicate names or an empty list), logs each one's position/quality/protection/autoreclose status right after construction, and runs a `google.golang.org/grpc` server on `Dms.Api.Scada.Grpc.{Host,Port}` with `internal/telemetryserver.TelemetryServer` registered as `pkg/telemetry`'s `TelemetryStream` service, plus an `internal/restserver` HTTP server on `Dms.Api.Scada.{Host,Port}`. Follows the shutdown pattern from the sibling `rdss-dms-rtdb` project: `signal.NotifyContext` → graceful shutdown (`http.Server.Shutdown`, `grpc.Server.GracefulStop`) with a timeout fallback to a hard `Stop()`. gRPC reflection is registered only when the log level is Debug or above.
- `internal/telemetryserver/` — implements both `TelemetryStream` RPCs. `telemetry.go`: `NewTelemetryServer(ctx, breakers, logger)` starts exactly one long-lived `forward` goroutine per breaker (tied to `ctx`, the application's overall lifetime context) that converts each `breaker.Event` to tags, logs it at Trace level (`logUpdate`) **exactly once**, and broadcasts it to every currently connected `Subscribe` client's own channel (`TelemetryServer.subscribers`, mutex-guarded) — regardless of how many clients are connected (zero, one, or many), so the trace log is never duplicated per client. `Subscribe` itself does no event-to-tag conversion; it only registers/unregisters a channel and relays what it receives, after sending (and logging) its own one-time initial snapshot. Event-to-tag mapping (`dataPointsForEvent`): `EventPositionChanged` refreshes only `"<name>.position"`; `EventMeasurementChanged` refreshes the analog tags; `EventControlBlocked`/`EventControlUnblocked` are the *only* source of `"<name>.blocked"` updates (re-read via `sim.Position()`'s quality, since neither event's `Detail` carries one) — deliberately not derived from `EventPositionChanged`'s `Quality` field even though `Block`/`Unblock` also emit that event, or every ordinary position change would resend an unchanged `.blocked` value; the remaining protection/autoreclose-related kinds trigger a cheap re-read via `ProtectionStatus()`/`AutoRecloseStatus()` rather than hand-decoding each `Detail` type. `SubstationRequest.Id` is ignored — every subscriber sees every configured breaker, since this simulator doesn't model a client/substation hierarchy. `control.go`: `SupervisoryControl` maps `key` = `"<breaker-name>.control"` and `value` (`0`=Open, `1`=Close) onto `BreakerController.Select`/`Operate`, tracking the pending `SelectionID` itself in `TelemetryServer.pending` (keyed by request `key`, mutex-guarded) since the proto message carries no field for a caller to echo one back; every call is logged at **Info** level twice (the request's key/value/flags, then the result, `moved` — whether the breaker's position actually changed, comparing `Position()` read before dispatch to after; false for a `Select`-only call or an `Operate`/`Test` that found the breaker already at target — and the breaker's *real, unmarked* position/quality/protection right before returning). `moved` exists so a caller can tell "did the switch flip" directly from this one log line rather than having to infer it by watching `"<name>.position"` for an `Intermediate` step on `Subscribe`. `Test` no longer means "validate only" — it always performs an immediate Select+Execute (same as Select+Execute both set) and calls `setTestMode(name, req.GetTest())` unconditionally on every call (not just `Test` ones): while a breaker's test mode is on, `applyTestMode` ORs `qds.QdsTest` onto every quality value `telemetry.go`'s point-builders (`breakerSnapshot`, `measurementPoints`, `statusPoints`, `dataPointsForEvent`) compute for it, on both `Subscribe`'s snapshot and every forwarded update, until a later call explicitly sets `Test` back to `false`. `EventPositionChanged` (`pkg/breaker`) fires not just on a real position change but also as a confirmation when `Operate` is a no-op (command already matches current position) — otherwise a SCADA client re-issuing a command matching the current state would see no push at all. See "SCADA tag naming" in `pkg/breaker/README.md` for the full `<breaker-name>.<category>.<leaf>` tag scheme, and note the quality-reduction rationale in `qualityToProto` (deliberately not `qds.Quality.GetPriority`, which serves a different, wider purpose).
- `internal/restserver/` — implements two endpoints from `api/scada/openapi.json`'s much larger REST API (see its package doc for what's out of scope). `POST /api/token`: an OAuth2-password-grant login (`username`/`password` form fields checked against `Dms.Api.Scada.{Username,Password}`) that hands back a freshly generated opaque bearer token — never actually validated anywhere afterward (neither this server nor `internal/telemetryserver`'s gRPC service checks it on any other call); it exists because real clients (e.g. `rdss-dms-rtdb/pkg/rest_client`) expect the login step to succeed and return a `TokenResponse`-shaped body. `GET /api/external/telemetry/tags`: every tag-id (with datatype) across every configured breaker, for provisioning a point before any data arrives via Subscribe — derived from `internal/telemetryserver.TagsFor` (the tag set `Subscribe`'s snapshot reports, plus the write-only `<name>.control` tag `SupervisoryControl` accepts, so it can be provisioned too even though it never appears in a Subscribe update), grouped under one fixed placeholder substation entry (`substationName = "scada-simulator"`) since this simulator has no real client/substation hierarchy, same simplification `Subscribe` makes for `SubstationRequest.Id`.
- `internal/configuration/` — the application's own config schema (`Configuration` struct: `Logging`, `Dms.Api.Database.Dsn`, `Dms.Api.Scada.{Host,Port,Username,Password,Grpc.Host,Grpc.Port}`, `Breakers` (`[]pkg/breaker.Config`, one per emulated breaker)), read via `pkg/configuration`. `config/scada-simulator.yaml` is a sample config file matching this schema, including a `breakers:` list.
- `pkg/configuration/` — a generic, standalone (own LICENSE) YAML + environment-variable configuration loader. Struct fields opt into env-var overrides via an `env:"true"` tag alongside their `yaml:"..."` tag; `ReadFromEnv`/`ListEnv` walk the struct with reflection to derive env var names from the nested yaml tags (parent tag + `_` + field tag, upper-cased, optionally prefixed with `EnvVarPrefix`). `Read(file, s)` loads the YAML file then applies env overrides on top. Only scalar fields (string/bool/int/[]string) support `env:"true"`; nested structs/arrays like `pkg/breaker.Config` are YAML-only.
- `pkg/llog/` — a standalone (own LICENSE) leveled logger wrapping the standard `log` package (`Trace`/`Debug`/`Info`/`Warning`/`Error`), with a package-level `Logger` singleton set up in `init()`. Log level is configured via `internal/configuration`'s `Logging.Level` field. `pkg/breaker` does not import this package directly — it declares its own minimal `breaker.Logger` interface (`Warnf`/`Errorf`/`Infof`) and defaults to a no-op logger; attach `llog.Logger` (or any other logger with that method set) via `breaker.Config{}.WithConfig(llog.Logger)`.
- `pkg/qds/` — SCADA point-quality bitflags (`Quality`, a `uint32`), e.g. `QdsInvalid`, `QdsNoSource`, `QdsSubstituted`, `QdsAlarmLl`/`QdsAlarmUl`, etc. `GetPriority()` picks a single representative flag from a set bitmask by priority order (for things like choosing a badge/border color). Has real unit tests in `qds_test.go` — follow this package's table-driven style when adding tests elsewhere. `pkg/breaker` reuses `qds.Quality` rather than defining its own.

### `api/scada/`

`telemetry.proto` is the gRPC contract `cmd/main.go`'s server implements (client/substation-scoped `Subscribe` point stream, plus `SupervisoryControl` for telecontrol commands); its generated Go code lives in `pkg/telemetry/` (`telemetry.pb.go`, `telemetry_grpc.pb.go` — `DO NOT EDIT`, regenerate from the `.proto` instead). `openapi.json` is the broader external RDSS SCADA/DMS backend's full REST API (250+ endpoints: telemetry, alarms, select/confirm/execute/cancel control, DMS status/LFA, etc.) — only `POST /api/token` and `GET /api/external/telemetry/tags` are implemented here (`internal/restserver`), the rest is not — grep it rather than reading it whole, it's large.

### `pkg/breaker`

An in-memory HV circuit breaker + protection relay (IED) simulator exposing a SCADA-facing interface (`scada.go`), implemented per the design spec in `tmp/hvcbagentprompt.md` (gitignored, present in this checkout only — consult it before extending the protection/autoreclose model). See `pkg/breaker/README.md` for the SCADA-requirement-to-interface mapping and how to run its `Example`. Key pieces: `types.go` (`Position`, `Measurement`), `protection.go` (IEC 60255 curves, `OperateTime`), `autoreclose.go` (pure ANSI-79 state machine), `control.go` (select-before-operate, `errors.AsType`-friendly error types), `config.go` (`Config`, YAML-loadable), `events.go`/`scada.go` (interfaces), `simulator.go` (the concrete `Simulator` — a single run-loop goroutine owns all state; external calls go through `do`/`doCtx` closures posted over a channel, which is what keeps it race-free without a mutex).

## Conventions

- MIT-licensed subpackages under `pkg/` (`pkg/llog`, `pkg/qds`, `pkg/configuration`) each carry their own `LICENSE` file and are written to be usable independently of this application — avoid introducing dependencies from these packages back onto `internal/` or `cmd/`.
- Table-driven tests, following `pkg/qds/qds_test.go`.
