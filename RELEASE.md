# Release Notes

- 2026-09-01: HV Breaker Simulator — Implemented `pkg/breaker`, an in-memory HV circuit breaker + protection relay simulator per `tmp/hvcbagentprompt.md`: SCADA-facing interfaces (position, analog, protection/autoreclose configuration, select-before-operate control, status, event subscription), IEC 60255 inverse-time and instantaneous overcurrent protection, an ANSI-79 autoreclose state machine, and a single-goroutine `Simulator` tying it together. Wired its `Config` into `internal/configuration.Configuration.Breaker` and the `breaker:` section of `config/scada-simulator.yaml` so breaker characteristics are YAML-configurable.
- 2026-09-01: Decouple Breaker Logging — `pkg/breaker` no longer imports `pkg/llog` directly. Added a minimal `breaker.Logger` interface (`Warnf`/`Errorf`/`Infof`), defaulted `Config.Logger` to a no-op implementation, and added `Config.WithConfig(logger Logger) Config` so callers attach a real logger (e.g. `pkg/llog.Logger`, which satisfies the interface as-is) without `pkg/breaker` depending on that package.
- 2026-09-01: Breaker Name for Logging — Added `Config.Name` (YAML `name`, defaults to `"breaker"`) and used it to prefix `pkg/breaker`'s internal log messages (`breaker[<name>]: ...`) so logs from multiple breaker instances are distinguishable. Populated `name` in `config/scada-simulator.yaml`.
- 2026-09-01: Breaker Blocked State — Added `Block(ctx, reason) error` / `Unblock(ctx) error` to `BreakerController`. Blocked state is tracked internally (`simState.blocked`/`blockReason`) and reflected as `qds.QdsBlocked` on the quality `Position()` returns, the measurement SCADA already polls. While blocked, `Select` and `Operate` are rejected with `*InterlockError`; a selection made before blocking survives it and can still be Operated after Unblock. Added `EventControlBlocked`/`EventControlUnblocked` events.
- 2026-09-01: Go 1.26 Modernization — Ran `go fix ./...` across `pkg/` and `internal/`. Applied the `rangeint` and `waitgroup` fixers to `pkg/breaker/simulator_test.go`'s concurrency test (`for i := 0; i < N; i++` → `for range N`; one `wg.Add(1)`/`go func(){defer wg.Done()...}()` → `wg.Go(func(){...})`). `cmd/` could not be processed — it has a pre-existing, unrelated `declared and not used: ctx` error blocking type-checking.
- 2026-09-01: Wire Up cmd/main.go — Fixed the `declared and not used: ctx` build error by actually using the shutdown context: `main` now constructs a `breaker.Simulator` from `config.Config.Breaker.WithConfig(llog.Logger)`, blocks on `<-ctx.Done()`, and closes it on SIGINT/SIGTERM. `go build ./...`/`go fix ./...` now succeed across the whole module.
- 2026-09-01: gRPC Server Scaffold — `cmd/main.go` now starts a `google.golang.org/grpc` server on `Dms.Api.Scada.Grpc.{Host,Port}`, registering `pkg/telemetry`'s `TelemetryStream` service with the generated `UnimplementedTelemetryStreamServer` (no RPC logic yet — every call reports `Unimplemented`). - 2026-09-01: Fix Logging Config Tag — `internal/configuration.Logging.Level` was tagged `yaml:"log"` but `config/scada-simulator.yaml` sets the key `level:`, so the configured log level (`trace`) was silently never read and the app always fell back to Debug. - 2026-09-01: Multiple Breakers — `internal/configuration.Configuration.Breaker breaker.Config` → `Breakers []breaker.Config` (`yaml:"breakers"`); the number of breakers emulated is simply `len(Breakers)`, no separate count field. `config/scada-simulator.yaml`'s `breaker:` block became a `breakers:` list with two example entries (`feeder-1`, `feeder-2`) with different protection/autoreclose settings. `cmd/main.go` now builds one `*breaker.Simulator` per entry into a `map[string]*breaker.Simulator` keyed by name (fatal on duplicate names), starting and closing them all. - 2026-09-01: SCADA Tag Naming Convention — Documented (not yet implemented — `Subscribe`/`SupervisoryControl` are still `Unimplemented`) the planned tag naming scheme in `pkg/breaker/README.md`: hierarchical, dot-separated, `<breaker-name>.<category>.<leaf>` (e.g. `feeder-1.power.reactive`, never an underscore-joined compound like `active_power`), covering position/blocked, three-phase current/voltage/power, frequency, protection and autoreclose status. `<name>.control` is deliberately a separate tag from `<name>.position` since a control point and a status point are distinct SCADA objects even for the same physical breaker.
- 2026-09-01: Implement Subscribe — Added `breaker.EventMeasurementChanged` (Detail is `Measurement`; fires on every `InjectMeasurement`), the one event kind Subscribe needed that didn't already exist. New `internal/telemetryserver.TelemetryServer` implements `TelemetryStream.Subscribe` per the documented tag scheme: sends a full-snapshot `SubstationUpdate` on connect, then pushes further updates as breaker events arrive (`PositionChanged`/`MeasurementChanged` map straight from their `Event.Detail`; `Trip`/`ProtectionPickedUp`/`AutoRecloseAttempt`/`Lockout`/`SettingsChanged` trigger a cheap re-read via `ProtectionStatus()`/`AutoRecloseStatus()` instead of hand-decoding each Detail type). `SubstationRequest.Id` is ignored — every subscriber sees every configured breaker, since this simulator has no client/substation hierarchy. Quality reduces via a new `qualityToProto`, deliberately distinct from `qds.Quality.GetPriority` (different purpose/priority order). `SupervisoryControl` remains `Unimplemented`. Added an integration test suite (real gRPC server + client over TCP) covering the initial snapshot, a measurement update, and a control-driven position update; full `go test -race ./...` and a real binary run both verified clean.
- 2026-09-01: Implement SupervisoryControl — New `internal/telemetryserver/control.go`. `key` must be `"<breaker-name>.control"` (`ERROR_OBJECT_IS_NOT_FOUND`/`ERROR_ITEM_IS_NOT_FOUND` if the breaker/suffix don't resolve); `value` is `0`=Open, `1`=Close (else `ERROR_NOT_SUPPORTED`). `select`/`execute` map onto `BreakerController.Select`/`Operate`; since the proto carries no field for a caller to echo a `SelectionID` back between the two calls, `TelemetryServer` tracks the pending one itself (`pending map[string]breaker.SelectionID`, keyed by `key`, mutex-guarded) — a request with both flags set performs both in one call, and `test` validates via Select+Cancel without arming anything. A pre-check against `qds.QdsBlocked` returns `ERROR_BLOCKED` before ever calling into `BreakerController`. Added `controlErrorResult` mapping the narrower set of `pkg/breaker` errors onto the proto's coarser result enum (several distinct cases necessarily collapse onto `ERROR_UNKNOW`). Added a full test suite (select-then-execute, combined select+execute, test, every error path, blocked); `go build`/`vet`/`gofmt`/`go test -race ./...` and a real binary run all verified clean.

- 2026-09-01: Stop Duplicating Subscribe Logs Per Client — Diagnosed a real report: with N clients connected, every breaker event was logged and converted N times (once per independent `Subscribe` RPC, each of which called `sim.Subscribe` and processed the event on its own). Side benefit: breaker activity is now logged even with zero clients connected. Updated `NewTelemetryServer`'s two call sites (`cmd/main.go`, `telemetry_test.go`) to pass the app's lifetime `ctx`. Verified end-to-end against the real binary with two concurrent `Subscribe` clients: exactly one `telemetry: update feeder-1.position` log line per transition, not two. Full `go build`/`vet`/`gofmt`/`go test -race ./...` clean.
